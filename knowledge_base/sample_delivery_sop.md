# Sample SOP: handling a potentially late delivery

> Demo-only document. This is an invented example for testing retrieval and grounding. It is not an official Olist or DataCo policy.

## Purpose

Provide an illustrative checklist for investigating an order that may arrive later than its estimated delivery date.

## Suggested review steps

1. Confirm the order identifier and the currently recorded shipping status.
2. Compare the estimated delivery date with the latest available carrier or delivery event.
3. Check whether the shipping event history is complete. Do not infer an event that is not recorded.
4. If the order is already beyond the expected date, flag it for human review and communicate only facts supported by the system.
5. Record the source and timestamp of any status information used in the review.

## Limits

This sample does not define contractual service levels, customer compensation, delivery guarantees, or an official escalation deadline. If the relevant policy is not available in the knowledge base, the assistant must say that there is not enough evidence and must not invent a policy.

## Example

Question: What should an operator check before escalating a potentially late delivery?

Expected evidence-based answer: Confirm the order ID, review the latest recorded shipping event against the estimated delivery date, and check whether the event history is complete. This is an illustrative checklist only.
